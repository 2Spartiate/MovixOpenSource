# Contrôle parental local V1

- Le PIN est composé de 6 à 8 chiffres. Le navigateur conserve un vérificateur PBKDF2-SHA-256 (310 000 itérations), avec un sel aléatoire de 16 octets. Les clés `movix_parental_pin_v1` et `movix_parental_preferences_v1` restent dans le `localStorage` de l'origine de cet appareil. Leur préfixe est bloqué par la synchronisation, préservé au chargement de profil et exclu de la copie des données locales. Les déverrouillages de médias restent dans un `Set` en mémoire JavaScript, indexé par type et identifiant TMDB ; ils disparaissent au rechargement.
- Cette protection est locale à l'interface. Elle ne constitue pas une autorisation côté serveur ni une protection des flux ouverts par d'autres applications, navigateurs ou appareils. Effacer le stockage local réinitialise le PIN. Un utilisateur contrôlant le navigateur ou ses données peut aussi contourner un verrou local ; un PIN court conserve un espace de recherche fini malgré la dérivation.
- Une classification connue est résolue en priorité depuis TMDB FR, puis US, puis les autres pays. Le verrou d'âge s'applique seulement si l'âge connu est strictement supérieur au seuil. En l'absence de classification vérifiée, le contrôle actif demande le PIN, quel que soit le seuil. Lorsque la règle Horreur est active, les genres et mots clés TMDB doivent également être disponibles ; un échec de métadonnées demande le PIN. Le genre film TMDB 27 est Horreur. Le genre TV 10765 (Science-fiction & Fantastique) ne l'est pas en lui-même. La restriction d'âge d'un profil reste prioritaire et ne peut pas être levée par ce PIN.
- Dans la SPA du dépôt, les routes de fiche et `/watch/movie`, `/watch/tv`, `/watch/anime` partagent le même garde React et la page de lecture attend les métadonnées. Le Home Anime remplace uniquement l'arrivée sur `/` quand les deux options correspondantes sont actives.

## Distribution dans l'application Android

Le frontend Vite (`src/**`) et l'application React Native (`app/**`) ont des distributions distinctes. `app/src/config/index.ts` pointe la WebView vers le site distant. Le workflow Android construit le frontend pour vérification, mais ne publie pas `dist/`. Les changements de la SPA seule ne deviennent donc pas visibles dans l'APK.

Le correctif natif `app/src/injection/parental-controls-runtime.ts` est désormais composé par `app/src/injection/inject.ts` dans `injectedJavaScriptBeforeContentLoaded` de la WebView, pour **téléphone, tablette et TV**. Il ajoute la section et les deux entrées de navigation au DOM de `/settings`, emploie les mêmes clés locales et le même format de vérificateur que la SPA, puis bloque les fiches et les lecteurs concernés. Il apprend la clé TMDB dans les requêtes du frontend existant et demande le PIN lorsque la classification ne peut pas être établie. Une route directe `/watch/...` est détournée vers sa fiche avant le démarrage du site ; les transitions SPA sont détournées vers cette fiche et la lecture HTMLMediaElement est suspendue tant que la décision n'est pas connue. Les adaptations de clavier numérique et de Back sont réservées à la TV.

Le build final doit vérifier que les marqueurs parentaux figurent dans le bundle autonome **à l'intérieur de l'APK**. Cette preuve établit la distribution du code injecté dans l'application installée, pas son rendu observé sur chaque appareil. La structure DOM et les échanges TMDB du site distant n'ont pas été inspectés en direct : le site protégé n'a pas été visité. Un essai sur téléphone et sur une vraie TV reste nécessaire pour confirmer le rendu, le focus et les lecteurs réels. Le site ouvert hors de l'application continue à dépendre du déploiement de la SPA modifiée.

Le typecheck intégral `tsconfig.app.json` est préexistant non vert : sa valeur `ignoreDeprecations: "6.0"` est invalide pour TypeScript 5.9.3 verrouillé dans ce dépôt et une correction temporaire révèle des erreurs antérieures sur de nombreux modules. Le contrôle `tsconfig.parental.json` vérifie réellement les utilitaires locaux, sans prétendre remplacer un contrôle intégral de la SPA.

Le workflow Android exécute les tests parentaux, le contrôle TypeScript ciblé, Gradle, les contrats manifest et un contrôle des marqueurs d'injection dans le bundle extrait de l'APK. La branche V1 est inscrite parmi les déclencheurs `push` ; les runs intermédiaires sont annulés par la concurrence du workflow lorsqu'un nouveau checkpoint est poussé.
