# Contrôle parental local V1

- Le PIN est composé de 6 à 8 chiffres. Le navigateur conserve un vérificateur PBKDF2-SHA-256 (310 000 itérations), avec un sel aléatoire de 16 octets. Les clés `movix_parental_pin_v1` et `movix_parental_preferences_v1` restent dans le `localStorage` de l'origine de cet appareil. Leur préfixe est bloqué par la synchronisation, préservé au chargement de profil et exclu de la copie des données locales. Les déverrouillages de médias restent dans un `Set` en mémoire JavaScript, indexé par type et identifiant TMDB ; ils disparaissent au rechargement.
- Cette protection est locale à l'interface. Elle ne constitue pas une autorisation côté serveur ni une protection des flux ouverts par d'autres applications, navigateurs ou appareils. Effacer le stockage local réinitialise le PIN. Un utilisateur contrôlant le navigateur ou ses données peut aussi contourner un verrou local ; un PIN court conserve un espace de recherche fini malgré la dérivation.
- Une classification connue est résolue en priorité depuis TMDB FR, puis US, puis les autres pays. Le verrou d'âge s'applique seulement si l'âge connu est strictement supérieur au seuil. En l'absence de classification vérifiée, le contrôle actif demande le PIN, quel que soit le seuil. Lorsque la règle Horreur est active, les genres et mots clés TMDB doivent également être disponibles ; un échec de métadonnées demande le PIN. Le genre film TMDB 27 est Horreur. Le genre TV 10765 (Science-fiction & Fantastique) ne l'est pas en lui-même. La restriction d'âge d'un profil reste prioritaire et ne peut pas être levée par ce PIN.
- Les routes de fiche et `/watch/movie`, `/watch/tv`, `/watch/anime` partagent le même garde. Tant que les métadonnées sont en cours de résolution, leur page et leur lecteur ne sont pas montés. Le Home Anime remplace uniquement l'arrivée sur `/` quand les deux options correspondantes sont actives.

## Distribution et preuve manquante

Le frontend Vite (`src/**`) et l'application React Native (`app/**`) ont des distributions distinctes. `app/src/config/index.ts` pointe la WebView vers `https://movix.tax`. Le workflow `.github/workflows/android-tv-foundations.yml` construit le frontend avec `VITE_SITE_URL=https://movix.example` pour vérification, mais ne publie pas `dist/`. Le bundle autonome de l'APK contient le shell React Native et les injections TV, **pas** la version modifiée de la SPA. Le dépôt et ses workflows ne fournissent aucun déploiement du frontend vers l'origine distante ni de preuve de la version servie. Le site protégé n'a pas été visité.

Pour livrer la fonction aux téléphones, tablettes et WebViews TV, l'exploitant de l'origine doit publier le frontend de ce HEAD sur cette origine, puis vérifier la version effectivement chargée sur chaque classe d'appareil. Un APK construit depuis cette branche avant cette publication est un artefact Android technique, sans preuve que les écrans parentaux y apparaissent.

Le typecheck intégral `tsconfig.app.json` est préexistant non vert : sa valeur `ignoreDeprecations: "6.0"` est invalide pour TypeScript 5.9.3 verrouillé dans ce dépôt et une correction temporaire révèle des erreurs antérieures sur de nombreux modules. Le contrôle `tsconfig.parental.json` vérifie réellement les utilitaires locaux, sans prétendre remplacer un contrôle intégral de la SPA.

Le workflow Android exécute les tests parentaux et ce contrôle TypeScript ciblé. Sa branche V1 est inscrite parmi les déclencheurs `push`, afin qu'un seul run du HEAD final soit produit par le dernier checkpoint quand `workflow_dispatch` n'est pas disponible dans le connecteur GitHub. Aucun run n'est lancé pour les checkpoints antérieurs de cette branche.
